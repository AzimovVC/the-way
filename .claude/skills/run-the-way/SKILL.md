# Запуск The Way

Мобильное PWA на Vite + React. Управляется **скриптом-драйвером**
[.claude/skills/run-the-way/driver.mjs](driver.mjs): он поднимает Chrome в headless
и говорит с ним по Chrome DevTools Protocol. Зависимостей нет — ни puppeteer, ни
playwright, ни `chromium-cli` тут не установлено, а CDP работает через встроенный в
Node WebSocket.

Пути ниже — от корня репозитория.

## Требования

Ничего доустанавливать не нужно. Достаточно того, что уже есть:

- Node 24 (нужен >= 22 — ради глобального `WebSocket`),
- Google Chrome в `/Applications/Google Chrome.app`. Другой путь — задайте `CHROME_BIN`.

```bash
npm install          # если node_modules отсутствует
```

## Запуск (путь агента)

Нужен работающий dev-сервер. Поднимите его **один раз** в фоне:

```bash
npm run dev          # занимает первый свободный порт начиная с 5173
```

Дальше всё делает драйвер. Команды подаются в stdin, по одной в строке:

```bash
printf 'goto\nss первый-экран\ntext #root\nquit\n' | node .claude/skills/run-the-way/driver.mjs
```

Он сам найдёт порт dev-сервера, снимет скриншот в телефонном вьюпорте (390×844, dpr 2)
и напечатает абсолютный путь к PNG — его можно сразу читать инструментом Read.

### Команды драйвера

| Команда | Что делает |
|---|---|
| `goto [url\|/путь]` | открыть приложение; относительный путь — от найденного сервера (`goto /stats`) |
| `ss [имя]` | скриншот, печатает абсолютный путь |
| `clickday <n\|today>` | клик по кругу дня на пути (`0` — самый старый) |
| `clicktext <текст>` | клик по элементу с этим текстом; регистр не важен |
| `click <css>` | клик по CSS-селектору |
| `type <css> <текст>` | ввод текста; селектор с пробелами — в `'одинарных кавычках'` |
| `text <css>` / `html [css]` | прочитать innerText / outerHTML |
| `wait <css> [мс]` | дождаться элемента |
| `eval <js>` | выполнить JS на странице |
| `state [expr]` | сохранённое состояние, **переждав debounce**; в `expr` доступна `s` |
| `seed` | записать готовую историю в 40 дней (цель, задача, провал в середине) |
| `seedtest` | засеять тестовую историю приложения: две цели с разным расписанием, выходные, спад и восстановление, сегодня не отмечено |
| `reset` / `reload` | очистить состояние / перезагрузить |
| `errors` | накопленные ошибки консоли и страницы |
| `quit` | закрыть браузер |

### Готовые сценарии

**Геометрия пути** — главное, ради чего стоит запускать приложение. `seed` сажает
40 дней с разгоном, провалом и восстановлением, поэтому дорога успевает развернуться
вниз и обратно вверх; `ОТДАЛИТЬ` показывает её целиком:

```bash
printf 'goto\nseed\nreload\nclicktext ОТДАЛИТЬ\nss путь-целиком\nquit\n' \
  | node .claude/skills/run-the-way/driver.mjs
```

**Карточка дня и отметка задачи** — сквозная проверка, что клик доходит до состояния:

```bash
printf 'goto\nseed\nreload\nclickday today\nclicktext Пробежка\nstate s.days.at(-1).tasks[0].isDone\nquit\n' \
  | node .claude/skills/run-the-way/driver.mjs
# -> false  (была true: задача переключилась и сохранилась)
```

**Готовая история с расписанием** — быстрее всего, когда нужно увидеть и рабочий день, и
выходной. То же самое даёт зелёная кнопка «Тестовая история» в DevPanel и вызов
`seedTestHistory()` из консоли браузера:

```bash
printf 'goto\nseedtest\nss тест\nquit\n' | node .claude/skills/run-the-way/driver.mjs
```

**Онбординг с нуля**, без `seed` — ровно то, что видит новый пользователь:

```bash
printf "goto\nreset\nclicktext Начать путь\nclicktext Спортсмен\nclicktext Далее\nclicktext Далее\nclicktext Добавить задачу\ntype 'input[placeholder=\"Название задачи\"]' Пробежка 3 км\nclicktext Сохранить\nclicktext Начать путь\nss путь-готов\nquit\n" \
  | node .claude/skills/run-the-way/driver.mjs
```

**Собранная версия**, а не dev — ловит то, что `npm run dev` пропускает:

```bash
npm run build && npm run preview          # -> http://localhost:4173/
APP_URL=http://localhost:4173/ printf 'goto\nseed\nreload\nss прод\nerrors\nquit\n' \
  | APP_URL=http://localhost:4173/ node .claude/skills/run-the-way/driver.mjs
```

**Панель разработчика** с ползунками геометрии (только в dev-сборке):

```bash
printf 'goto\nseed\nreload\nclicktext 🛠 dev\nss девпанель\nquit\n' \
  | node .claude/skills/run-the-way/driver.mjs
```

## Запуск (путь человека)

```bash
npm run dev     # открыть напечатанный URL в браузере, Ctrl-C для остановки
```

Приложение мобильное — в браузере включите эмуляцию телефона, иначе путь читается иначе,
чем на целевом устройстве.

## Сборка и тесты

```bash
npm run test     # 108 тестов, ~3 с — инварианты геометрии пути
npm run lint     # oxlint; сейчас выдаёт предупреждения, код выхода 0
npm run build    # tsc -b && vite build
```

## Ловушки

- **`npm run dev` не проверяет типы.** Vite не зовёт `tsc`, поэтому ошибка компиляции
  живёт в репозитории незаметно, пока кто-нибудь не соберёт проект. На момент написания
  скилла `npm run build` падал на неиспользуемом импорте в `PathView.tsx` — при зелёном
  dev-сервере и зелёных тестах. Перед коммитом гоняйте именно `build`.

- **Портов может быть несколько, и это молча ломает состояние.** Vite берёт первый
  свободный порт от 5173, а забытые с прошлых сессий серверы сдвигают адрес — здесь их
  одновременно работало три. `localStorage` привязан к origin, то есть к порту: записать
  историю на `:5173` и открыть `:5175` — значит увидеть пустой онбординг вместо своих
  данных. Поэтому в `goto` передавайте **относительный** путь (`goto /stats`), а не
  собранный руками URL. Проверить, кто занял порты:
  `lsof -nP -iTCP:5173 -iTCP:5180 -sTCP:LISTEN`.

- **Запись в localStorage дебаунсится на 400 мс** (`SAVE_DEBOUNCE_MS` в
  [src/storage/appStorage.ts](../../../src/storage/appStorage.ts)). Прочитать хранилище
  сразу после клика — значит прочитать прошлое: `eval` вернёт прежнее значение, и будет
  выглядеть, будто клик не сработал. Для проверки состояния всегда берите `state`, она
  пережидает окно.

- **Карточка дня выезжает 300 мс** (`duration-300` в `DayCard.tsx`). Клик по ещё едущему
  элементу промахивается — и молча: элемент найден, координаты взяты из промежуточного
  положения, обработчик не вызван, драйвер рапортует `ok`. Драйвер лечит это сам, дожидаясь
  конца CSS-переходов через `document.getAnimations()`. Если добавляете свои клики через
  `eval`, помните об этом.

- **Заглавные подписи — это CSS.** Кнопка внизу выглядит как «ОТДАЛИТЬ», но в DOM лежит
  «Отдалить»: заглавные делает `text-transform: uppercase`. Поэтому `clicktext` сравнивает
  без учёта регистра — искать можно как на экране.

- **SVG пути — не первый `<svg>` на странице.** Раньше него идут иконки, поэтому
  `document.querySelector('svg')` даёт иконку, а не путь. Нужен `svg[width="100%"]`.

- **У дней нет стабильных селекторов** — это SVG-группы без `id`, `data-*` и `aria-label`.
  `clickday` находит их по форме: группа дня содержит ровно два круга (подставка и лицо),
  у призрака будущего — один. Если разметку дня поменяют, чинить надо там.

- **Онбординг перехватывает все маршруты.** Пока нет ни одной цели с задачей, `/stats` и
  `/profile` тоже показывают онбординг: в `App.tsx` проверка `needsOnboarding` стоит выше
  роутера. Поэтому `seed` идёт до перехода на другой экран, а не после.

## Если что-то не так

| Симптом | Причина и что делать |
|---|---|
| `dev-сервер не найден на портах 5173-5180` | не запущен `npm run dev`, либо он занял другой порт — задайте `APP_URL=http://localhost:PORT/` |
| `Chrome не поднял отладочный порт 9333` | другой путь к Chrome (`CHROME_BIN=...`) или порт занят прошлым прогоном (`CDP_PORT=9334`) |
| Открылся онбординг вместо пути | состояние писалось на другой порт или ещё не было `seed`; см. ловушку про порты |
| Клик прошёл, а состояние прежнее | читали `eval`-ом внутри окна debounce — возьмите `state` |
| `приложение не смонтировалось за 15 с` | ошибка в рантайме — посмотрите `errors` |
| `текст не найден` | текст разбит на несколько узлов; ищите более короткий фрагмент (`Пробежка` вместо всей строки) |
