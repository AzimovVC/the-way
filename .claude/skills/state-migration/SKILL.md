# Изменение схемы сохранённого состояния

## Чем это опасно

Всё состояние живёт в localStorage под ключом `the-way:v1` в конверте
`{ version: 1, state }`. Бэкенда нет — **localStorage и есть единственная копия данных
пользователя**. Потерянный прогресс не восстановить ниоткуда.

Чтение идёт через [migrate.ts](../../../src/storage/migrate.ts) и заканчивается одним из трёх
исходов: `ok` (запись прочитана, при необходимости проведена по цепочке вверх), `empty`
(ничего не было сохранено — первый запуск) и `unreadable`. Разница между вторым и третьим —
вся суть этого слоя: `empty` начинает человека с нуля, `unreadable` сначала откладывает его
запись целиком в `the-way:quarantine`, а профиль и онбординг предлагают её скачать.

Что из этого следует:

- **Поднять `version`, не добавив шаг в `MIGRATIONS`, — не катастрофа, но полный отказ.**
  Чтение вернёт `unreadable`, запись уйдёт в карантин, человек увидит пустой путь и
  предложение забрать отложенную запись файлом. Данные целы, но приложение не работает:
  это баг, который надо чинить шагом миграции, а не отпускать в релиз.
- Добавить обязательное поле, не подняв версию, — оставить старые записи с `undefined`
  там, где типы обещают значение. Проверка формы в `isPlausibleState` намеренно
  поверхностная (есть `user.goals`, есть `days`) и такого не ловит: строгая проверка
  отправляла бы в карантин вполне рабочие записи, а это ровно та беда, от которой всё и
  строилось. TypeScript тоже не поможет — содержимое localStorage приходит как `unknown`.

## Как решать

**Необязательное поле** (`newGoalIds?`, `milestonesReached?` — уже так сделаны):
версию не трогаем, читатели обрабатывают `undefined` (`?? []`). Самый дешёвый путь —
предпочитайте его, когда он подходит.

**Обязательное поле, переименование, смена формы:** нужна миграция. Механика уже есть,
дописать надо мало:

1. Поднимите `CURRENT_VERSION` в [migrate.ts](../../../src/storage/migrate.ts) до N+1.
2. Добавьте в `MIGRATIONS` шаг под ключом N — чистую функцию из формы версии N в форму
   N+1. Она принимает `unknown`: на этом этапе запись доказанно объект нужной версии и
   больше ничего.
3. Возьмите **настоящий** JSON из браузера (`localStorage.getItem('the-way:v1')`),
   положите как фикстуру рядом с `__fixtures__/v1-snapshot.json` и проверьте в
   [migrate.test.ts](../../../src/storage/migrate.test.ts), что дни и цели после
   миграции целы. Старые фикстуры не трогайте — они и есть страховка.
4. `loadState` сам запишет мигрированную запись обратно, чтобы цепочка не проигрывалась
   при каждом запуске. Ничего дописывать для этого не нужно.

Чего делать **нельзя**: возвращать `createEmptyState()` на непонятную запись, смягчать
отказ при дырке в цепочке, расширять `isPlausibleState` до полной валидации схемы.

      (`pathAngleDelta`, `columnDriftX`, `colorTier`) считаются из истории через
      `applyPathGeometry` — их незачем расширять новыми хранимыми полями.

## Что ещё стоит знать про этот слой

- Запись дебаунсится на 400 мс; `beforeunload` и `pagehide` дожимают её принудительно.
  Добавляя новый путь выхода из приложения, зовите `flushPendingSave()`.
- `AppStateContext.setState` пишет в хранилище **всегда**. Отдельного «сохранить» нет —
  и не надо его добавлять.
- Восстановление пропущенных дней (`reconcileMissedDays`) и авто-заморозки выполняются
  один раз при монтировании провайдера. Новое поле, которое должно появляться у каждого
  дня, нужно проставить и там — иначе задним числом созданные дни будут отличаться от
  созданных обычным путём.
- Ключ `the-way:v1` содержит версию в имени. Если вы когда-нибудь смените сам ключ,
  старый останется в браузере мусором — читайте старый, мигрируйте, удаляйте.
- Ключ `the-way:quarantine` хранит **первую** отложенную запись и намеренно не
  перезаписывается: ко второму отказу приложение уже записало поверх основного ключа
  пустое состояние, и новый карантин сохранил бы именно его.
- Пользовательская копия (`BackupSection`) читается тем же `readEnvelope`, поэтому файл
  из старой версии мигрируется при восстановлении так же, как запись из localStorage.
  Восстановленное состояние проходит через `rollForwardToToday`.
- Настройки DevPanel (`pathTuning.ts`) лежат в localStorage **отдельными** ключами и к
  этому конверту отношения не имеют.
