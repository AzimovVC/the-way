## Что уже решено про часть 5

Спрошено у владельца 22 сентября, ответы записаны здесь, потому что решать это второй раз нельзя:

- **глубина ленты друзей — 7 дней.** Неделя — единица времени во всём приложении (Пн–Вс, недельные
  итоги, значки `Н1`, `Н2`), и лента, показывающая ровно ту неделю, о которой говорят остальные
  экраны, не заводит шестой отрезок времени. Числу место в `config.ts`; **настройки для человека у
  него нет** — глубина ленты не то, о чём он что-то решает, а «показать ещё» на дне списка — это
  уже архив чужой жизни, от которого лента и отделялась;
- **сердце своему событию поставить можно.** Владелец выбрал это, зная цену: счёт становится
  накручиваемым. Значит, «кому понравилось» рисуется **лицами, а не числом** — лица говорят, кто
  именно, и своё лицо среди двух чужих никого не обманывает, а «3» обманывает.

## Первое, что надо сделать, — доспросить форму ленты

Владелец на вопрос «в какую вкладку ложится событие про пару» ответил встречным: «Feed это и про
друзей, и про пользователя». То есть под вопросом само разделение на «Ты» и «Друзья» из решения 6.

Предложено (и не подтверждено): **одна лента без вкладок, и твои события подрезаются той же
неделей.** Тогда Feed — «что случилось за неделю, у тебя и у них»: один список, одна глубина, одно
правило сортировки, и вопрос «куда ложится событие про пару» исчезает вместе с вкладками. Твой
глубокий архив при этом не теряется — он и есть дорога, где каждый день круг, на который можно
нажать, плюс архив недель по значкам и экраны месяцев. Лента, уходящая на полгода назад,
пересказывает дорогу другими словами.

Цена названа: пролистать свой июнь текстом станет негде.

**Это первый ход следующего чата — подтвердить или отклонить, а не начать писать.** От ответа
зависит и то, где живёт прощальная карточка о выходе из кружка, и `buildFeed`, который сейчас
читает всю историю.

## Чего делать нельзя

- **Ничто из `src/social/` не попадает в `AppState`.** Её отметка не влияет ни на `completionRate`,
  ни на цвет, ни на угол, ни на серию, ни на веху. Это несущее правило, а не осторожность.
- **Сообщения чеканит сервер, человек — никогда.** Политик на вставку в `notices` нет ни у кого, и
  заводить их нельзя: таблица, в которую пишет человек, — канал свободного текста в чужое
  приложение. Сердце этого правила не отменяет: оно не текст, а одно значение.
- **RLS включается в том же файле, что и `create table`**, до первой строки данных.
- **`sb_secret_…` в приложение не попадает никогда.**

## Как тут работают

- `psql` и supabase CLI нет: SQL выполняет владелец руками в SQL Editor. Миграция пишется файлом в
  `supabase/migrations/`, дальше — просьба прогнать.
- Перед коммитом: `npm run lint && npm run test && npm run build`.
- Коммит: английский заголовок в повелительном наклонении, тело по-русски про **почему**, трейлер
  `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- PR не открывать. Работаем в `main`, пуш по просьбе.
- Проверять живьём — скилл `run-the-way`. Он поднимает Chrome по CDP и снимает экран; для этого
  `.env.local` приходится временно отодвигать, иначе дверь требует Google.
